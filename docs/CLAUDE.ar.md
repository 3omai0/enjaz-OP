# ربط إنجاز مع Claude (MCP)

يضيف هذا الموصّل إنجاز إلى Claude، فتكتب أو تتكلم في Claude وهو ينفّذ في إنجاز مباشرة: إنشاء المهام وإسنادها وتحريكها بين الحالات، التعليقات، قوائم التحقق، المشاريع والأعضاء، والإشعارات.

يعمل Claude **باسم الشخص الذي ربطه وبصلاحياته نفسها**. كل عملية تمر عبر منطق التطبيق ذاته، فتصل الإشعارات للفريق ويُسجَّل النشاط كما لو نُفّذت من الواجهة، والموظف لا يستطيع عبر Claude ما لا يستطيعه في الواجهة.

## التشغيل لأول مرة

1. طبّق الترحيل الجديد على قاعدة الإنتاج: `npm run db:migrate` (يضيف جدولي `mcp_clients` و`mcp_connections`).
2. انشر التطبيق كالمعتاد. لا يحتاج متغيرات بيئة جديدة؛ يستخدم `AUTH_SECRET` الموجود.
3. يجب أن يكون التطبيق على رابط عام بـ HTTPS (مثل نطاقك على Vercel)، لأن Claude يتصل من خوادمه.
4. اختياري: إن كان التطبيق خلف وكيل لا يمرّر اسم النطاق، اضبط `APP_URL=https://نطاقك` حتى تخرج الروابط صحيحة.

## الربط من Claude (لكل شخص)

1. في إنجاز: **الإعدادات ← الربط مع Claude**، وانسخ رابط الموصّل. صيغته: `https://نطاقك/api/mcp`
2. في Claude: **Settings ← Connectors ← Add custom connector**، الصق الرابط وسمّه «إنجاز».
3. اضغط **Connect**؛ تفتح صفحة إنجاز، سجّل دخولك واضغط «السماح».
4. انتهى. الموصّل متاح في Claude على الويب والجوال وسطح المكتب.

لفصله: من إعدادات إنجاز ← «التطبيقات المتصلة» ← «فصل». تغيير كلمة المرور أو تعطيل الحساب يفصله تلقائيًا.

## الأدوات المتاحة لـ Claude

| الأداة | ما تفعله |
| - | - |
| `whoami` | المستخدم الحالي ودوره وتاريخ اليوم |
| `list_projects`، `get_project` | المشاريع، أعضاؤها، تصنيفاتها وأعداد المهام |
| `list_people` | الأشخاص النشطون للإسناد |
| `list_tasks`، `get_task` | البحث في المهام وتفاصيل مهمة |
| `create_task`، `update_task`، `delete_task` | إنشاء وتعديل وحذف المهام |
| `add_comment`، `add_checklist_items`، `set_checklist_item` | التعليقات وقوائم التحقق |
| `create_project`، `add_project_members` | المشاريع والأعضاء (للمدير ومدير المشاريع) |
| `list_notifications` | إشعاراتك، مع خيار تعليمها كمقروءة |

## كيف يعمل (للمطوّر)

- نقطة MCP: `src/app/api/mcp/route.ts` (Streamable HTTP بدون جلسات). الأدوات في `src/lib/mcp/server.ts`.
- تسجيل الدخول OAuth 2.1: تسجيل ديناميكي للعميل (`/api/oauth/register`)، صفحة موافقة (`/oauth/authorize`)، PKCE إلزامي، رموز وصول لمدة ساعة، ورموز تحديث تتبدّل مع كل استخدام (`/api/oauth/token`). بيانات الاكتشاف على `/.well-known/oauth-protected-resource` و`/.well-known/oauth-authorization-server`.
- تُنفَّذ الأدوات عبر الإجراءات الموجودة في `src/lib/actions` بعد ضبط «المستخدم المنفِّذ» (`src/lib/auth/acting.ts`)، فلا يوجد منطق صلاحيات مكرر.
- رمز الوصول موقّع بمفتاح مشتق من `AUTH_SECRET` ومختلف عن مفتاح جلسات المتصفح، فلا يعمل أحدهما مكان الآخر. لا يُحفظ في القاعدة إلا تجزئات الرموز.

## حل المشاكل

- **Claude يقول تعذّر الوصول للخادم:** افتح `https://نطاقك/.well-known/oauth-protected-resource` في المتصفح؛ يجب أن يظهر JSON يحتوي `resource` مطابقًا تمامًا للرابط الذي أضفته في Claude.
- **فشل الموافقة بعد تسجيل الدخول:** تأكد أن الترحيل طُبّق على قاعدة الإنتاج.
- **الروابط في ردود Claude تشير لعنوان خاطئ:** اضبط `APP_URL`.
