# دليل التشغيل والنشر

## 1. المتطلبات والتشغيل المحلي

ثبّت Node.js 22 مع npm وGit إن أردت نسخ المستودع. افتح الطرفية داخل المجلد الذي يحتوي package.json. على Windows يمكن استخدام PowerShell، وعلى macOS/Linux الطرفية المعتادة.

```sh
npm ci
npm run setup
npm run dev
```

افتح http://localhost:3100/setup. أدخل اسم المدير وبريده وكلمة مروره وتأكيدها (8 أحرف على الأقل). ينشئ النظام الحساب ويسجّل دخوله. صفحة الإعداد تعمل فقط ما دامت قاعدة المستخدمين فارغة. من الفريق أنشئ حسابات الموظفين بكلمات مرور مؤقتة واطلب منهم تغييرها من الإعدادات. أضف مشروعًا وحدد أعضاءه ثم أنشئ المهام.

قاعدة PGlite المحلية تُنشأ وتُحدّث تلقائيًا في `.data/pglite`. أوقف الخادم بـ Ctrl+C. لا تشغّل خادمين أو أداة seed مع الخادم على القاعدة المحلية نفسها. هذه القاعدة للتطوير؛ وضع الإنتاج يتطلب Neon.

## 2. إنشاء قاعدة الإنتاج في Neon

1. أنشئ حسابًا في https://neon.com ثم مشروعًا جديدًا وقاعدة مستقلة لهذا التطبيق.
2. من لوحة المشروع اختر Connect وانسخ رابط الاتصال بقاعدة البيانات (pooled connection string).
3. شغّل `npm run setup` إن لم تكن أنشأت `.env` ثم ضع الرابط في `DATABASE_URL` داخل هذا الملف. احتفظ بخيارات الرابط مثل sslmode.
4. أوقف خادم التطوير ثم طبّق الترحيلات:

```sh
npm run db:migrate
npm run dev
```

5. افتح `/setup` وأنشئ مدير قاعدة البيانات الجديدة. تغيير الرابط لا ينقل بيانات القاعدة المحلية إلى Neon.

التطبيق يستخدم مشغّل Neon HTTP؛ لا تفترض أن PostgreSQL محليًا أو أي مزود آخر يعمل بمجرد تغيير الرابط. أمر `db:migrate` هو مسار تحديث قاعدة الإنتاج. `db:push` أداة تطوير ولا يُنصح باستخدامها بدل سجل الترحيلات في الإنتاج.

## 3. متغيرات البيئة

| المتغير | الاستخدام |
|---|---|
| AUTH_SECRET | مطلوب: سر عشوائي لا يقل عن 32 حرفًا، يولده setup |
| DATABASE_URL | فارغ للتطوير المحلي، رابط Neon مطلوب للإنتاج |
| CRON_SECRET | سر للجدولة، يولده setup؛ يجب أن يطابق قيمة مجدولك |
| VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY | اختياريان لتفعيل إشعارات الجهاز |
| VAPID_SUBJECT | عند تفعيل الإشعارات ضع mailto: متبوعًا ببريد إدارتك الحقيقي |
| NEXT_PUBLIC_APP_TIMEZONE | منطقة IANA مثل Asia/Riyadh (الافتراضي) أو Europe/London؛ اضبطها قبل البناء |
| SEED_ADMIN_NAME / EMAIL / PASSWORD | تخص البيانات التجريبية فقط، وليست حساب الدخول العادي |

لا ترفع `.env` أو نسخة قاعدة البيانات إلى GitHub. استخدم أسرارًا مستقلة لكل تثبيت. تغيير AUTH_SECRET يُبطل الجلسات الحالية.

## 4. النشر على Vercel

ارفع هذا المجلد كمستودع مستقل ثم استورده في Vercel كـ Next.js، مع Node.js 22. أضف متغيرات البيئة في إعدادات المشروع: DATABASE_URL وAUTH_SECRET، وCRON_SECRET للمهام المتكررة، ومتغيرات VAPID إن أردت إشعارات الأجهزة. استخدم قاعدة منفصلة لبيئات المعاينة، ولا تربط معاينات مساهمين بقاعدة الإنتاج.

طبّق `npm run db:migrate` محليًا باستخدام رابط قاعدة الإنتاج قبل نشر نسخة تحتاج ترحيلات. ثم انشر، وافتح `/setup` لإنشاء المدير. احمِ النشر الأول بقيود الوصول في منصة الاستضافة إلى أن تنتهي من إنشاء المدير، لأن أول زائر للقاعدة الفارغة يستطيع إنشاء الحساب.

الملف `vercel.json` يطلب تشغيل الجدولة كل دقيقة. تأكد أن خطتك تدعم ذلك؛ إن لم تدعمه، احذف خاصية `crons` من الملف واستخدم مجدولًا خارجيًا كما في القسم التالي.

لخادم Node.js مستمر مع Neon وHTTPS عبر وكيل أمامي:

```sh
npm ci
npm run setup
# اضبط DATABASE_URL وبقية القيم في .env أولاً
npm run db:migrate
npm run build
npm run start
```

المنفذ الافتراضي 3100. احتفظ بعملية الخادم قيد التشغيل بواسطة مدير خدمات مناسب. وضع الإنتاج يستخدم ملفات تعريف ارتباط آمنة ويجب تقديمه عبر HTTPS.

## 5. المهام المتكررة

التعريف وحده لا يشغّل المهام. اضبط مجدولًا يرسل GET كل دقيقة إلى:

```
https://YOUR-DOMAIN.example/api/cron/recurring
Authorization: Bearer YOUR_CRON_SECRET
```

أو أرسل الترويسة `x-cron-secret` بالقيمة نفسها. لا تضع السر في عنوان الرابط. Vercel Cron يرسل قيمة CRON_SECRET تلقائيًا عند ضبطها. بعد ذلك أنشئ مهمة متكررة من الواجهة وتحقق من ظهور المهمة والتذكير في موعدهما. المواعيد الفائتة بأكثر من يوم تُتجاوز بحسب منطق التطبيق.

## 6. إشعارات الأجهزة

```sh
npx web-push generate-vapid-keys
```

ضع المخرجات في VAPID_PUBLIC_KEY وVAPID_PRIVATE_KEY واضبط VAPID_SUBJECT إلى بريد تواصل حقيقي مثل `mailto:you@your-domain.example`. أعد تشغيل التطبيق أو نشره. احتفظ بالمفاتيح ثابتة؛ تغييرها يتطلب إعادة الاشتراك على الأجهزة. من إعدادات حسابك فعّل الإشعارات واستخدم الإشعار التجريبي. يلزم HTTPS في النشر، وإذن المتصفح، وقد يحتاج الجهاز تثبيت التطبيق على الشاشة الرئيسية. الإشعارات الداخلية تعمل بدون VAPID.

## 7. بيانات تجريبية واستعادة الدخول

اختياريًا وعلى قاعدة فارغة فقط، أوقف خادم التطوير ثم شغّل `npm run db:seed`. ينشئ حسابات ومشاريع وهمية بعناوين example.com؛ كلمات المرور العشوائية تظهر مرة واحدة في الطرفية. لا تستخدم البيانات التجريبية لمساحة فريق حقيقية. لا تشغّل seed إذا كنت تريد إنشاء مديرك من /setup.

لاستعادة كلمة المرور مع وصول إداري للخادم وملف .env الصحيح:

```sh
npm run reset-password -- admin@your-domain.example
```

اتبع الإدخال التفاعلي؛ كلمة المرور الجديدة تُخرج الحساب من جميع الأجهزة. إن كان هناك مدير واحد يمكن تشغيل الأمر بدون البريد.

## 8. التحديث والنسخ الاحتياطي

خذ نسخة احتياطية من Neon أو استخدم وسائل الاستعادة المتاحة في حسابك قبل الترحيلات. احتفظ بالأسرار خارج المستودع. للقاعدة المحلية أوقف جميع العمليات أولًا ثم انسخ مجلد `.data` كاملًا. اختبر استعادة النسخ في بيئة منفصلة.

عند التحديث: راجع التغييرات، ثبّت الاعتماديات بـ `npm ci`، طبّق الترحيلات، ثم افحص وابنِ وأعد النشر. لا تحذف بيانات القاعدة لإصلاح مشكلة عادية.

## 9. رفع نسخة مستقلة إلى GitHub

أنشئ مستودعًا عامًا فارغًا بدون README إضافي. نفّذ داخل **هذا المجلد**:

```sh
git init
git add .
git status
# راجع الملفات المعروضة وتأكد من غياب .env و.data
git commit -m "Initial open-source release"
git branch -M main
git remote add origin https://github.com/3omai0/enjaz-OP.git
git push -u origin main
```

لا تنسخ مجلد .git من أي مشروع آخر. ترخيص MIT يسمح بالاستخدام والتعديل والتوزيع مع الاحتفاظ بإشعار الترخيص. GitHub Actions يفحص الكود ويبنيه عند الدفع وطلبات الدمج.

## 10. حل المشكلات

- خطأ AUTH_SECRET: شغّل setup إن لم يوجد .env؛ إن كان موجودًا أصلح القيمة يدويًا. لتوليد سر: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
- /setup مغلقة: توجد حسابات بالفعل؛ سجّل الدخول أو استخدم reset-password.
- فشل الاتصال بـ Neon: تحقق من الرابط والمشروع والشبكة وتطبيق الترحيلات.
- قفل PGlite: أوقف النسخ الأخرى من الخادم وأدوات القاعدة.
- المنفذ مستخدم: أوقف الخدمة المتعارضة أو شغّل `npm run dev -- --port 3101`.
- لا تظهر المهام المتكررة: تحقق من استدعاء المجدول والسر والمنطقة الزمنية.
- تستخدم الواجهة خطوط الجهاز ويمكن تخصيصها في src/app/globals.css.
- للتمييز بين عطل إعداد وعطل كود شغّل `npm run lint` ثم `npm run typecheck` ثم `npm run build`.
